# 来源引用

所有来源引用的首要目的，是帮助用户直接跳转到支持附近观点或素材的准确页码、时间、行号或原始资源位置。引用是面向用户的导航，不是装饰性元数据，也不是需要完成的格式配额。

因此，应把每个引用自然融入正文、图注或来源说明，并放在它实际支持的观点或素材附近。不要把引用作为机械标签悬挂在句末或段末。

引用还应让读者在不使用 ReadOS 跳转功能时，也能从可读文字中理解资料出处。

## 自然呈现

- 让页码、时间或行号成为来源“提到、解释、展示、比较或支持”附近观点的位置，不要先写完一句话再追加裸标签。
- 根据语境选择自然表达，例如“教材第 11 页用……解释了……”“视频在 12:08 展示了……”“notes.txt 第 42 行明确限制了……”。这些只是示例，不是固定模板。
- 同一段连续依赖同一来源时，在最自然的位置集中引用，不要每句话重复相同标签。
- 图注和来源说明可以简洁，但必须可读，并明确对应图片、公式、表格或引用内容的真实出处。
- 只为真正依赖具体资料的主张、公式、数据、原文、代码或插图添加来源，不要为了显得严谨而机械增加引用数量。

## 默认行为

- 保持 `\readexlinkstrue`，除非用户明确要求禁用 ReadOS 链接或制作可在外部独立使用的便携文档。
- 禁用链接时，仍保留 `教材第 11 页`、`视频 12:08` 或 `notes.txt 第 42 行` 等可读文字。
- 只有用户明确要求完全不显示引用时，才删除可读来源文字。

## 路径写作与稳定跳转

在模型编写的 LaTeX 中只使用普通工作区路径，保持路径本身，不做额外改写或编码。第一次编译后，ReadOS 会根据来源路径建立稳定跳转，使链接在来源移动或重命名后仍可恢复，并将原路径保留为回退信息。

使用模板宏：

```tex
\readexpdfsource{/教材/SwiftUI基础.pdf}{11}{教材第 11 页}
\readexvideosource{/视频/SwiftUI课程.mp4}{728}{视频 12:08}
\readextextsource{/笔记/notes.txt}{42}{notes.txt 第 42 行}
\readeximagesource{/图片/架构图.png}{原图}
\readexfilesource{/资料/示例代码.swift}{示例代码}
```

引用视频或文本范围时，使用范围宏：

```tex
\readexvideosourcerange{/视频/SwiftUI课程.mp4}{728}{746}{视频 12:08--12:26}
\readextextsourcerange{/笔记/notes.txt}{42}{48}{notes.txt 第 42--48 行}
```

路径是普通 Linux 路径。包含空格、中文或其他合法文件名时，按 LaTeX 对宏参数的正常要求书写；不要额外编码或拼接内部信息。

## 来源记录

每张从工作区资料或网页来源取得、裁剪或转换的来源派生正式插图，以及每处资料引用，都应包含可读来源上下文或 ReadOS 链接。ReadOS 会自动维护对应的来源记录。裁图或转换后的视频帧会保留：

- 原始来源路径
- 页码、时间范围或行号范围
- 适用时的归一化裁剪矩形
- 请求的视频时间和实际视频时间
- 派生素材路径

这些信息由 App 记录。你仍需判断证据是否支持附近的教学结论，以及应如何支持。

模型自行绘制或生成、且不依赖特定资料的纯概念示意图，不要为了引用配额伪造来源。若图中的内容、数据或构图实质依赖具体资料，仍应在附近如实引用该资料。

## 网页来源

凡在讲义中实际采用的联网资料，都要在它所支持的内容附近自然附上可读的来源名称和可点击链接，不要只在文末堆放一组无法对应正文的 URL。对公开网页使用普通 HTTPS 链接；只有网页已经是具有稳定内容身份的工作区资源时，才使用 ReadOS 内容链接。
