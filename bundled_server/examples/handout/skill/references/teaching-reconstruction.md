# 教学重构

像一位优秀教师重新备课那样写作，不要只压缩字幕、摘抄资料或拼接分段摘要。保留必要的技术深度，但先用通俗语言建立直觉，再引入正式定义、公式、代码和复杂机制。

## 教学质量标准

- 以你对主题的理解为主重新备课、判断和组织内容。原始资料是重要证据与教学素材，但不是讲义结构、解释方式和教学深度的上限。
- 通常依靠已有知识和给定资料完成重构，不要把联网搜索当作例行步骤。只有关键知识无法可靠判断，或明显具有时效性、存在重要冲突、疑似错误且会影响讲义正确性时，才检索可信来源核实或作必要补充。
- 将实际采用的联网资料自然整合进讲解，并按照 `source-citations.md` 在相关内容附近附上可读来源和可点击链接；不要让外部资料变成与主线割裂的资料堆叠。
- 让读者感到有一位耐心、清楚、技术可靠的教师在引导，而不是面对原始资料的缩写版。
- 解释讲者或资料为什么引入一个概念、它解决什么问题，以及下一步为什么自然地从这里展开。
- 追求“深入但可理解”：保留关键机制和技术细节，不要用空泛比喻替代准确解释，也不要在直觉尚未建立时直接堆砌形式化内容。
- 对密集主题使用多个递进小节逐层建立理解，不要把所有定义、公式、推导和例子压进一个长段落。
- 优先保证教学覆盖、逻辑完整和可读性，不要为了缩短篇幅而删掉理解机制所必需的解释。
- 原始资料的篇幅分配不等于教学重要性。资料对某个概念、前提、推理步骤或机制只是一带而过、默认读者已经知道或没有讲清时，只要它对理解主线、后续内容或关键结论必不可少，就依靠你对主题的理解主动补足背景、直觉、步骤、例子、边界和常见误区，直到目标读者能够顺利理解。不要为了逐句忠于资料而保留原材料的讲解缺口。
- 不要因此扩写每个随口提及的旁支。只详细补充影响学习目标和主线理解的内容，并清楚区分原始资料实际表达的内容与自己的补充解释；使用联网资料时仍须按照 `source-citations.md` 附上来源和可点击链接。
- 根据用户目标决定深度。入门材料要补足前置直觉；进阶材料可以减少常识解释，但仍要交代假设、边界和关键推理。

## 写作前建立教学地图

在大量写作前，先完成以下判断：

1. 明确读者读完后应该理解什么、能够解释什么或能够完成什么。
2. 区分核心主线、必要前置知识、支持案例、可选延伸和应删除的无关内容。
3. 为每个重要结论找到实际来源依据，并标出适合使用的公式、代码、图表、截图或案例。
4. 识别资料中的重复、互补、矛盾、缺口和术语差异。
5. 先形成统一教学大纲，再决定资料出现顺序；不要边读边按来源顺序直接生成正文。
6. 对证据不足或存在歧义的内容保留不确定性，不要擅自补成确定事实。

## 核心概念的展开顺序

对每个主要概念，按适用情况依次回答以下问题：

1. **问题与动机**：正在解决什么问题？这个问题为什么重要？
2. **旧理解的局限**：更简单的方法、直觉或已有概念为什么不足？
3. **直觉模型**：读者在看到正式表达前，应先建立怎样的通俗心智模型？
4. **核心观点**：用最短而准确的话说明定义、主张或机制。
5. **工作机制**：分步骤解释它如何运行、各部分如何相互作用，以及因果关系在哪里。
6. **例子或证据**：使用来源支持的案例、公式、代码、图表或演示把机制具体化。
7. **边界与误区**：说明适用条件、限制、常见错误和容易混淆的近似概念。
8. **要点**：压缩读者应保留的结论，以及现在应该能够完成的任务。

不要机械地给每个微小概念套用全部八项；但主要概念必须形成从问题到结论的完整教学闭环。

## 逻辑过渡与章节组织

- 不要把章节写成相邻知识点的列表。进入新概念时，说明它是在解决上一节遗留问题、补充必要前提、推广已有结论、修正错误直觉，还是转向实际应用。
- 在复杂推理中显式写出关键连接词和因果关系，避免让读者自行猜测两段内容为什么相邻。
- 一个小节只承担一个清楚的教学任务。主题发生实质变化时新开小节，不要用超长段落掩盖结构。
- 先给整体路线，再解释局部机制；解释完局部后，再回到整体说明它处于什么位置。
- 先解释“为什么”，再解释“是什么”和“怎么做”；只有用户明确要求速查手册时，才可以明显压缩动机和推导。
- 章节标题应表达教学问题或核心概念，避免使用“其他”“补充”“更多内容”等缺少信息的标题。

## 长资料与多资料整合

- 可以分段理解长视频、长 PDF、书籍或大量文本，但必须把分段结果重新整合成一份统一大纲和连贯叙事。
- 保留相邻分段之间必要的上下文，在整合阶段删除重复解释并补足逻辑过渡。
- 多个来源重复时，选择最清楚的解释作为主线，在有教学价值时引用其他来源作为补充证据。
- 一份资料提供直觉、另一份提供公式或案例时，把它们合并成同一条教学链，不要按文件分别写成互不相连的章节。
- 来源发生冲突时，判断是事实冲突、术语差异、假设不同、适用范围不同，还是资料版本不同。只有冲突影响学习时才展开说明，并保留各自主张的来源。
- 不要为了让文字更顺滑而虚构共识，也不要把多份资料的相似说法错误地当作相互独立的证据。

## 教学内容取舍

优先保留：

- 核心定义、机制、因果关系和设计权衡
- 能改变读者理解的例子、反例和失败案例
- 讲者或资料明确强调的关键限制、误区和实践建议
- 能解释结构、变化或比较关系的公式、代码和图表
- 有教学价值的结尾讨论，如综合、限制、未来方向、开放问题和下一步建议

删除或大幅压缩：

- 问候、录制说明、平台互动和例行结束语
- 不影响理解的重复口头表达和填充内容
- 与用户学习目标无关的旁支讨论
- 只增加篇幅、没有新增机制或证据的同义反复

## 数学内容

出现重要公式时按以下顺序处理：

1. 先用通俗中文解释公式试图表达什么，以及为什么此处需要它。
2. 再给出清楚的展示公式，不要把关键公式埋在长段落中。
3. 紧接着逐一解释所有符号，保持列表平整，不要让符号定义散落在远处。
4. 说明假设、定义域、单位、取值范围和适用条件；这些因素不影响解释时才可省略。
5. 解释重要的极端情况、边界情况或参数变化如何影响结果。
6. 优先给出一个简短但完整的计算例子，而不是未经讲解的长推导。
7. 最后回到当前教学问题，说明公式带来了什么判断、预测或实际能力。

不要只贴公式并写“其中”，也不要把资料中的公式当作装饰性权威符号。

## 代码内容

- 在代码清单前解释代码解决什么问题、输入是什么、输出是什么，以及它在整体机制中的角色。
- 除非完整程序本身就是教学对象，否则只展示课程所需部分。
- 使用语法高亮和说明性 `caption`，让读者不依赖上下文也能知道代码用途。
- 在代码后解释关键执行顺序、重要状态变化和预期行为。
- 说明边界情况、失败方式、容易犯的实现错误，以及必要的性能或安全权衡。
- 代码只是机制的证据或实现，不要让长代码清单替代概念解释。
- 能从代码中提炼出可迁移原则时，明确指出该原则如何应用到其他场景。

## 插图与证据

- 每张重要插图都必须支持附近正文中的一个具体教学主张。
- 插图出现前说明为什么需要看它；插图之后说明应观察什么、为什么重要，以及应得出什么结论。
- 不要用装饰性截图代替解释，也不要仅为证明“看过资料”而堆放图片。
- 一张图信息过载时，使用多个必要视图、局部裁图或分阶段说明，不要缩小到标签不可读。
- 对展示变化过程的材料，只有过程本身具有教学价值时才保留多个阶段；否则选择最完整、最清楚的状态。
- 图中可见内容与正文描述不一致时，以实际证据为准并修正文案，不要强行解释不存在的元素。
- 候选帧、裁图质量和可读性要求遵循 `figure-selection.md`，来源文字和跳转链接遵循 `source-citations.md`。

## 教学提示框

- 使用 `importantbox` 强调读者必须带走的核心概念，例如正式定义、中心主张、关键机制、重要算法步骤和密集解释后的压缩结论。
- 使用 `knowledgebox` 补充有助于理解但不属于主线的背景，例如前置知识、历史脉络、工程背景、设计权衡、术语比较和直觉类比。
- 使用 `warningbox` 说明常见误解、隐藏假设、误导性启发、实现陷阱、因果混淆和容易出错的边界情况。
- 提示框没有每节一个的配额；有多个独立教学信号时可以使用多个，没有具体教学价值时一个也不要使用。
- 将提示框放在产生该结论的解释、推导或案例之后，避免在证据出现前先给口号。
- 普通讲解保留为正文。提示框用于高信号内容，不用于装饰；图片不要放进提示框。

## 章节小结与最终综合

- 每个内容充分的主要章节都以 `\subsection{本章小结}` 或语义等价的小节收束。
- 本章小结要压缩核心观点、机制和它们之间的关系，并说明读者现在应该能够理解或完成什么；不要只重复章节标题。
- 有一到两个真正有价值的外部资源时，可以增加 `\subsection{拓展阅读}`，不要为了形式完整而堆放链接。
- 文档最后使用 `\section{总结与延伸}` 或语义等价的顶级章节。
- 最终综合必须包含来源中有教学价值的结尾讨论，删除例行结束语。
- 加入对核心主张、机制和实际意义的结构化提炼，而不是复制各章小结。
- 建立章节之间的联系，压缩全文的概念结构，并在证据支持、推理边界清楚的前提下给出谨慎推广。
- 资料支持时，说明实际应用、限制、权衡、开放问题、后续实践和下一步学习方向。

## 禁止的写法

- 不要机械保留字幕、页码、章节或文件顺序。
- 不要把分段摘要、文件摘要或来源摘要直接拼成最终讲义。
- 不要用公式、代码、截图和提示框制造虚假的“内容丰富”。
- 不要重复解释相同内容，也不要为了显得详细而扩写空话。
- 不要把推测写成来源支持的事实，不要删除影响结论的限制条件。
- 不要省略主要概念之间的逻辑过渡。
- 不要输出 `[cite]` 一类占位符，也不要留下尚未解释的教学草稿标记。
