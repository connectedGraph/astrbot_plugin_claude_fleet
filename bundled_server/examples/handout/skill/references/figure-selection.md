# 插图选择

## 通用原则

检查的候选图应多于最终保留的数量。最终插图必须相关、完整、清晰，并优于附近的其他候选图。本 Skill 以文字与代码块为主，插图是增强而非必需；没有合适素材时不要为插图而插图。

## 检查图片

需要理解或检查图片内容时，直接使用当前会话的视觉能力（把图片作为输入查看）。逐张确认：

- 相关性：图片是否支撑当前观点。
- 完整性：标签、图例、边框、公式编号是否齐全，是否被裁切。
- 清晰度：小字、公式、代码、边缘是否可读，有没有过度压缩或放大模糊。
- 裁剪：候选图是否因为裁剪丢掉了必要信息。

视觉文件存在或命令成功不代表检查通过；必须根据实际看到的内容判断。

## 模型生成的教学插图

只在生成的示意图、概念图、情境图或封面视觉确实有助于教学时使用生图能力。不要用装饰性图片挤占正文空间，也不要用生成图替代本可直接引用的准确原始图表、公式、代码或界面证据。

1. 生图优先使用当前会话可用的原生生图能力；语法不确定或调用被拒绝时，明确说明并调整提示词，不要假装图片已生成。
2. 生成后把正式图片放到当前项目的 `./assets/`，候选放 `/tmp/readex-lecture/`，文件名语义清楚。
3. 每次生成完成后都必须实际检查构图、主体、数量关系、文字、符号和教学含义；涉及小字、公式、标签、代码或边缘细节时放大检查。不合格时修改提示词或放弃该图，不能仅因生成成功就采用。
4. 将模型生成图明确视为教学示意图，而不是原始资料的视觉证据。不要为生成图伪造 PDF 页码、视频时间或 ReadOS 来源跳转；如果构图或事实实际采用了联网资料，仍须在附近自然附上相应来源和可点击链接。

## 从 PDF 取图（简化）

本 Skill 首版以文字讲义为主。当确实需要从 PDF 截图作为插图时：

1. 先用 `ocrcli --json <pdf>` 查看布局与结构，定位目标页。
2. 用环境可用工具（如 `pdftoppm`、ImageMagick `convert`）把目标页渲染成图片，或从会话能力中裁剪所需区域。
3. 将候选放到 `/tmp/readex-lecture/`，检查后把正式图放入 `./assets/`。
4. 标签、边框、图例、公式编号或必要图注被截断时调整裁剪；条件允许时在 LaTeX 中插入矢量裁剪 PDF。

扫描页和纯栅格图无法真正转成矢量图。保留来源像素，避免重复 JPEG 压缩，并在最终版面中检查有效 DPI。

## 视频素材（首版不处理）

本 Skill 首版不处理视频抽帧。资料为视频且无法通过字幕/转写读取时，明确说明该限制；不把均匀抽帧冒充成对口述内容的完整理解。

## 格式

- 幻灯片、代码、图表、UI、文字和线稿使用 PNG。
- 只有文件大小确实重要时，才对照片类素材使用高质量 JPEG。
- 来源矢量裁图和生成的图表尽量使用 PDF。
- 不要为了报告更大的分辨率而放大低分辨率素材。
